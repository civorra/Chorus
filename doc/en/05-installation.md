# Installation & runtime environment

## Installing Chorus

Chorus is installed from source, via git. There is no other distribution
channel: the Perl classes on GitHub are not systematically propagated to
CPAN — **do not install Chorus from CPAN**. The git repository is the only
source of truth for both the Perl engine (`lib/`) and the AI-assisted
pipeline (`agent/skills/`, `agent/org/`).

```sh
git clone https://github.com/civorra/Chorus
cd Chorus
perl Makefile.PL && make && make test && make install
```

This gives you the complete framework:

- `lib/` — the Perl inference engine: `Chorus::Engine`, `Chorus::Frame`,
  `Chorus::Expert`
- `agent/skills/` — the `chorus-*` skills (`chorus-feed`, `chorus-check`,
  `chorus-pdf`…) loaded by an AI agent
- `agent/org/` — KB templates and the agent ontology
- `sandboxes/01-demo_en` and `sandboxes/02-nephro-KDIGO-compliance` — two
  full working examples, ready to run

## Runtime dependencies

The inference engine itself is pure Perl 5.006+, with no dependency beyond
the Perl core and a handful of standard CPAN modules (`YAML`, `Scalar::Util`,
`Digest::MD5`). Once a pipeline has been generated by `chorus-check`, it runs
entirely standalone:

```sh
# On any machine with Perl installed — no AI agent, no network:
perl run.pl project.json
```

This is the whole point of the two-phase design: the AI agent is only
involved in **Phase A** (building the KB and rules from a corpus). **Phase B**
(running a project through the generated pipeline) is deterministic Perl,
nothing more.

## Recommended environment — ECA

The `chorus-*` commands are AI agent skills, not shell scripts — they need
to be loaded and executed by an AI coding agent. Chorus itself is agent-agnostic
and the skills were first validated from a terminal session with Claude Code
and with GitHub Copilot. That said, the environment actually used day to day
for developing and running Chorus is **[ECA](https://eca.dev)** (Editor Code
Assistant) — an editor-agnostic AI coding agent that runs inside Neovim,
IntelliJ, VS Code. Whichever editor you use, the
difference ECA makes is not subtle: having the agent operate directly
inside the editor — same buffers, same project context, same keybindings —
turns what used to be a copy-paste loop between a terminal and an editor into
a genuinely fluid, single-surface workflow. Multi-file skill execution,
incremental sandbox generation, org-mode KB editing — all of it just feels
like a natural extension of the editor rather than a bolted-on tool.

If you are choosing a setup to run Chorus's AI-assisted pipeline, ECA — in
whichever editor you already work in — is the configuration this project
actually recommends. See <https://eca.dev> to get started.

## Summary

| | |
|---|---|
| **Install from** | git only — `git clone` + `make` |
| **Do not install from** | CPAN (not systematically in sync with GitHub) |
| **Engine runtime dependency** | Perl 5.006+ and standard CPAN modules only |
| **Generated pipeline runtime** | Perl alone — no AI agent, no network |
| **Recommended AI agent environment** | [ECA](https://eca.dev) (Neovim, IntelliJ, VS Code) |
