#+TITLE: Chorus — Architecture & Decisions
#+DATE: 2026-07-24

* Overview — Two distinct phases
  :PROPERTIES:
  :CATEGORY: Architecture
  :END:

#+begin_example
Phase A — Build        [AI agent, supervised, once per corpus]
  Raw corpus → chorus-feed → KB (org) + YAML rules + Perl infrastructure
             → chorus-check → deployable Perl pipeline

Phase B — Execution    [Chorus alone, no LLM, for each project]
  project.json → perl run.pl → compliance report
  100% deterministic · reproducible · certifiable
#+end_example

The LLM only intervenes in Phase A. In Phase B: no LLM, no network,
identical result for two identical runs.

* $ENGINE — Shared Frame prototype
  :PROPERTIES:
  :CATEGORY: Architecture
  :COMPONENT: Chorus::Engine
  :END:

All =Chorus::Engine= methods (=loop=, =addrule=, =solved=, =cut=...)
are **closures on a prototype Frame** =$ENGINE= defined at package level.

=new()= creates a plain Frame then makes it inherit from =$ENGINE=:
#+begin_src perl
my $res = Chorus::Frame->new(_RULES => [], @_);
$res->_inherits($ENGINE);
#+end_src

Consequences:
- Every engine instance shares methods via Frame inheritance.
- =$SELF= in these methods always points to the current instance.
- Multiple inheritance is possible (e.g. also inheriting from a config Frame).

* $SELF — Global context variable
  :PROPERTIES:
  :CATEGORY: Architecture
  :COMPONENT: Chorus::Frame
  :END:

=$SELF= is a global variable managed by =Chorus::Frame= via a stack
(=pushself= / =popself=). It points to the Frame whose method is currently executing.

** In YAML rules
=$SELF= points to the **engine** (engine instance) throughout the entire ACTION block.
Guaranteed since v2.01 (see pitfalls.org §_APPLY coderef).

** In procedural Frame slots
=$SELF= points to the Frame whose slot is being evaluated:
#+begin_src perl
my $f = Chorus::Frame->new(
    label => sub { "Frame " . $SELF->{_KEY} }
);
#+end_src

** In hooks (_AFTER, _BEFORE, _NEEDED)
=$SELF= points to the Frame that owns the hook.

* _RULES / _QUEUE — Master list vs working queue separation
  :PROPERTIES:
  :CATEGORY: Architecture
  :COMPONENT: Chorus::Engine
  :END:

- =_RULES=: master rule list, populated by =addrule()=. **Never modified** during =applyrules()=.
- =_QUEUE=: working copy built at each =applyrules()= call. Consumed by =$apply_rec=.

This separation allows =cut()= / =last()= / =replay()= to drain the queue
without affecting the master list for the next cycle.

* applyrules() — Combinatorial loop via eval (v2.0.2+)
  :PROPERTIES:
  :CATEGORY: Architecture
  :COMPONENT: Chorus::Engine
  :COMPLEXITY: O(n) where n = number of rules; per-rule complexity = O(2^k) k=scope arity
  :IMPLEMENTATION: String eval, recursive descent with tail call
  :END:

The Cartesian product of scopes is generated at runtime via string =eval=:

#+begin_src perl
# Dynamically builds a nested loop for the Cartesian product:
my $i = 0;
my $head = 'JUMP: {' . join('',
    map { 
        'foreach my $k' . (++$i) . ' (@{$scope{' . $_ . '}}) {$opt{' . $_ . '}=$k' . $i . ';' 
    }
    keys(%scope)
);

# Body: _APPLY call (plain coderef since v2.01)
my $body = '$res = do { my $_af = $rule->{_APPLY}; $_af ? $_af->(%opt) : 0 };' .
           'if ($res && $rule->{_TERMINAL}) { $SELF->solved() ... } ' .
           'last JUMP if $SELF->{_LAST} or $SELF->{_CUT} or ...';

# Close the loops
my $tail = '}' x scalar(keys(%scope)) . '}';

eval $head . $body . $tail;
#+end_src

** Implementation details (v2.0.2)

| Element | Role | Since |
|---|---|---|
| =JUMP:= label | Enables =cut()= via =last JUMP= (exits all nested loops at once) | 2.0.0+ |
| =$_af = $rule->{_APPLY}= | Plain coderef call, not Frame dispatch (=$SELF= stays on engine) | 2.01 |
| =_log_fire()= wrapper | Closure injected around =_APPLY= at =addrule()= time | 2.0.2 |
| =$apply_rec= recursion | Mutually-final recursion: consumes =_QUEUE= linearly | 2.0.0+ |
| =_QUEUE= working copy | Distinct from =_RULES= (master list) — enables =cut/last/replay= | 2.0.0+ |

** Performance and cost

- **String eval cost**: ~1 µs per rule (amortised over a full cycle)
- **Cartesian product cost**: exponential in scope arity → limit to 3–4 variables max
- **Memory**: single eval compiles and executes → no intermediate bytecode storage

** Flow-control flags

| Flag | Set by | Effect | Cleared by |
|---|---|---|---|
| =_CUT= | =cut()= | Exits nested loops (=last JUMP=) | after each rule |
| =_LAST= | =last()= | Drains =_QUEUE=, moves to next agent | after queue reset |
| =_REPLAY= | =replay()= | Drains =_QUEUE=, restarts current agent | by =Expert::process()= |
| =_REPLAY_ALL= | =replay_all()= | Drains =_QUEUE=, restarts from first agent | by =Expert::process()= |

* BOARD — Shared inter-agent memory
  :PROPERTIES:
  :CATEGORY: Architecture
  :COMPONENT: Chorus::Expert
  :END:

=BOARD= is a =Chorus::Frame= shared across all agents, injected by =register()=.
Accessible from any rule via =$agent->BOARD= or =$SELF->BOARD=.

** Reserved slots
| Slot | Set by | Meaning |
|---|---|---|
| =SOLVED= | =solved()= | Success — stops =process()=, returns =1= |
| =FAILED= | =failed()= | Failure — stops =process()=, returns =undef= |
| =INPUT= | =process($input)= | Raw pipeline input value |

** Convention
Domain knowledge (facts about specific objects) goes on individual Frames,
not on BOARD. BOARD = pipeline-level flags and counters.

* process() loop — Expert orchestration
  :PROPERTIES:
  :CATEGORY: Architecture
  :COMPONENT: Chorus::Expert
  :END:

#+begin_src
do {
  for each agent in _agents:
    if _LOCK_UNTIL_STABLE and any previous agent succeeded → skip
    do { agent->loop() } while agent->_REPLAY
    push agent onto @processed
    if agent->_REPLAY_ALL → delete flag, break (restart from agent 0)
} until BOARD.SOLVED or BOARD.FAILED
#+end_src

** _LOCK_UNTIL_STABLE
Flag on an agent — it only runs if no preceding agent succeeded in this iteration.
Useful for fallback or final-validation agents.

* Forward chaining vs backward chaining
  :PROPERTIES:
  :CATEGORY: Architecture
  :COMPONENT: Chorus::Engine
  :END:

Chorus implements only **forward chaining** (data-driven):
rules fire when their scopes find matching Frames.

** Existing proto-backward building blocks
- =_NEEDED= on Frame: local lazy eval, no engine-level propagation
- =_PREMISSES= on rule: metadata not consumed by =applyrules()=
- =_AFTER= on Frame: forward propagation, opposite direction
- CoW (Copy-on-Write): available for simulation

** Architectural decisions settled (2026-07-03)

| Decision | Choice |
|---|---|
| D1 — =PRODUCES:= | Declarative in YAML (no static inference) |
| D2 — =%RULE_PRODUCES= scope | Per agent (={_RULE_PRODUCES}= on the engine) + optional merge at =register()= |
| D3 — =_MUTABLE= granularity | List =_mutable: [slot, ...]= in project JSON; Perl API: =_MUTABLE= flag per slot |
| D4 — =_EXPLAIN= injection | Closure wrapper in =addrule()= first; string eval in =applyrules()= in phase 2 |
| D5 — =Chorus::Planner= | Separate module =lib/Chorus/Planner.pm= |

See report =2026-07-03-backward-chaining-deep-chorus.md= for the full analysis.

** Backward-chaining roadmap (v2.x)

Retained implementation order:

1. =PRODUCES:= in YAML DSL + =_PRODUCES= on the rule Frame  ← =Engine.pm::codeRule()=
2. =_MUTABLE= flag (project JSON + loader)                   ← parallelisable with 1
3. =%RULE_PRODUCES= in =loadRules()= after the for loop       ← depends on 1
4. =_EXPLAIN= closure wrapper in =addrule()=                  ← independent
5. =_EXPLAIN= empty scopes (string eval in =applyrules()=)    ← phase 2, medium risk
6. =Chorus::Planner= — =lib/Chorus/Planner.pm=                ← depends on 1+2+3

Lightweight alternative (parallelisable after step 2 only):
CoW simulation — clone Frame + re-run =process()=, without =Chorus::Planner=.

* Inter-frame relations — Patterns A and B
  :PROPERTIES:
  :CATEGORY: Architecture
  :COMPONENT: Feed.pm / Chorus::Frame
  :ADDED: 2026-07-23 (feat/relations-inter-frames)
  :END:

A Frame can carry a **reference to another Frame** of a different type,
allowing YAML rules to navigate laterally across domain objects.

** Pattern A — slot → Frame (structural link)

#+begin_src perl
# In Feed.pm load_projet() — %REF_FIELDS field + two-pass loading
my %REF_FIELDS = (
    link_ref => { slot => 'link_slot', type => 'target_type' },
);
# Pass 1: Frames without *_ref
# Pass 2: *_ref resolution + $source->set('link_slot', $TYPED_FRAMES{$id})
#+end_src

YAML navigation: =$f->get('link_slot')->get('remote_slot')=
Option A fallback: =$target ? $target->get('remote_slot') : $f->get('local_slot')=

** Pattern B — _ISA prototype (Minsky)

#+begin_src perl
# Static prototype catalogue (holds normative thresholds)
# $inject_isa called in BOTH passes (not only pass 2)
my $inject_isa = sub {
    my ($frame, $spec_key_1, $spec_key_2) = @_;
    my ($proto) = fselect(
        _from => \@catalog,
        _test => sub { $SELF->{spec_key_1} eq $spec_key_1 && ... }
    );
    $frame->_inherits($proto) if $proto;
};
#+end_src

YAML navigation: =$f->get("threshold_slot_$cond")= → inherits from prototype via =_ISA=.

** Pattern B safety constraint

Prototypes must **not** carry the targeting slot (=besoin_X=) —
otherwise =fmatch(slot => 'besoin_X')= would also return prototypes in the scope.

** Backward compatibility

=*_ref= fields are **always optional** — never in =%SLOTS_REQUIS=.
See pitfalls.org §=*_ref in %SLOTS_REQUIS=.

* Code Density & Compactness Analysis (v2.0.2 — 2026-07-24)
  :PROPERTIES:
  :CATEGORY: Architecture
  :ANALYSIS_DATE: 2026-07-24
  :SOURCE: Full source review (Engine.pm, Expert.pm, Frame.pm)
  :END:

Chorus is a **highly compressed** platform — three classes (~1900 lines total)
implement a complex architecture without sacrificing readability.

** Metrics by class

| Class | Total LoC | Code % | Compactness | Maintainability |
|---|---|---|---|---|
| Frame.pm | 1200 | 54% | 9/10 | 8/10 |
| Engine.pm | 550 | 55% | 9/10 | 7/10 |
| Expert.pm | 150 | 67% | 9/10 | 9/10 |
| **Total** | 1900 | ~55% | **9/10** | **8/10** |

** Key compactness highlights

*** Frame::_setN (Copy-on-Write inline)
~40 lines for complex logic:
- Distinguishes owner Frame from inherited one via =_PARENT_KEY=
- Creates shadow Frames on the fly for non-destructive mutations
- Multi-step path with inheritance traversal

*** Frame::_expandInherits (Valuation chain)
~15 lines to walk _VALUE → _DEFAULT → _NEEDED across the inheritance tree.
Elegant combination of _first() + recursion.

*** Engine::applyrules (Cartesian product via eval)
~60 total lines including:
- String generation of the Cartesian product
- Logging wrapper closure injection
- Tail-call recursion on _QUEUE

*** Expert::process (Multi-agent orchestration)
~30 lines for:
- do/until loop with implicit priorities (_LOCK_UNTIL_STABLE)
- _REPLAY and _REPLAY_ALL handling
- SOLVED/FAILED flag cleanup

** Architecture observations

| Observation | Implication |
|---|---|
| **Global registries** (%REPOSITORY, %FMAP, %INSTANCES) | O(1) lookups but memory overhead (weak refs everywhere) |
| **Dynamic N/Z modes** | Flexibility at minimal cost (one global flag) |
| **_SELF context stack** | Enables inheritance traversal without explicit parameters |
| **String eval in applyrules()** | Code generated once per cycle, cost amortised; no static bytecode optimisation |
| **Closure wrapper for logging** | Non-intrusive: injected at addrule(), transparent to _APPLY |
| **JUMP: label trick** | Perl-idiomatic: exits N nested loops in one instruction |

** Comparison with other inference engines

| Engine | LoC | Style | Notes |
|---|---|---|---|
| Chorus (Frame+Engine+Expert) | 1900 | Perl 5 + YAML DSL | Very compact; pure forward-chaining |
| CLIPS (C) | ~50k | C + forward-chaining | More mature; built-in backward-chaining |
| Jess (Java) | ~30k | Java + Jess DSL | Heavier OO; more infrastructure |
| SWI-Prolog | ~100k | Prolog | Native recursion; different purpose (logic) |

Chorus targets a **sweet spot**: compact enough to be fully understandable,
expressive enough for real-world domains (compliance, diagnostics).

* CPAN Distribution — Scope
  :PROPERTIES:
  :CATEGORY: Architecture
  :END:

The =Chorus= distribution (formerly =Chorus-Engine= < v2.01) contains:

| Component | Module | Role |
|---|---|---|
| Inference engine | =Chorus::Engine= | Recognise-act cycle, rules, YAML DSL |
| Orchestrator | =Chorus::Expert= | Multi-agent, shared BOARD |
| Frames | =Chorus::Frame= | Typed objects, inheritance, CoW (separate =Chorus-Frame= dist.) |
| Collections | =Chorus::Collection::List/Filter= | Ordered sequences, pattern matching |
| AI companion | =agent/= | Skills + KB templates for corpus→compliance pipeline |

=Chorus::Frame= is in a separate CPAN distribution (=Chorus-Frame=) — declared as a
dependency in =Makefile.PL=.
