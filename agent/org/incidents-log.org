* cc314-01 — Frame-local targeting slot not propagated to BOARD, 41 CONDITION always false (chorus-check Step 5d)
:PROPERTIES:
:sandbox:  05-CC-3.1.4
:date:     2026-10
:skills:   chorus-check.md § Step 5d
:END:

> **Incident (2026-10, sandbox `05-CC-3.1.4`):** `toe-structure` published
> `besoin_conformite` as a Frame-local slot on `ST`/`PP`/`TOE` Frames only. 41
> rules across 11 downstream SFR class agents — each generated by a separately
> delegated sub-agent during a large multi-agent `chorus-feed` pass, none with
> full pipeline visibility — read it via `CONDITION: defined $e->{besoin_conformite}`
> on their own, different Frame types (`FAU_GEN.1.1`, `FCO_NRO.1`, …). Every
> one of the 41 `CONDITION`s evaluated permanently false. The pipeline still
> "ran" — `perl run.pl` produced no error — but `Chorus::Expert::process()`
> looped for 10+ minutes (observed) with growing memory before being manually
> killed; a controlled diagnostic with `max_iter` forced down to 1-100
> confirmed the BOARD never received a single downstream phase-done flag.
> Fix: publish `$SELF->BOARD->{besoin_conformite} = 1` in `toe-structure`'s own
> rule (kept the Frame-local copy too, for `ST`/`PP`/`TOE`-local traceability),
> and changed all 41 downstream `CONDITION`s to read `$SELF->BOARD->{besoin_conformite}`.
> Confirmed fix: full pipeline `SOLVED` in 0.18s post-fix, vs. non-convergent
> before. This check exists so the next sandbox catches the same bug class at
> `chorus-check` generation time, mechanically, before any `perl run.pl` is
> ever attempted.

* cc314-06 — BOARD-flag self-refiring, 13-minute hang (chorus-check Step 5i)
:PROPERTIES:

:date:     2026-10
:skills:   chorus-check.md § Step 5i
:END:

> **Incident (2026-10, sandbox `05-CC-3.1.4`):** all 19 non-final agents'
> `mark-phase-done-and-terminate` rule (one per SFR/SAR class agent, excluding
> `conformance-ctrl`) published its own BOARD phase-done flag
> (`sfr_operations_phase_done`, `sar_content_phase_done`, `eal_package_complete`)
> in `ACTION`, but the `EXCEPTION` tested only "no pending Frame remains" —
> never `defined $SELF->BOARD->{<flag>}`. Once the aggregation condition
> became permanently true (expected, mid-pipeline), each rule's `ACTION`
> re-fired on every remaining engine cycle up to `_MAX_CYCLES` (10000),
> cumulatively producing a 13+ minute hang with climbing memory (~30% RSS)
> and zero stderr output beyond the initial Feed load — indistinguishable
> from the outside from the Step 5d/5e/5f bug classes already documented,
> but caught by none of their scans (no `$agent->` misuse, flag *was*
> correctly BOARD-scoped and read, aggregation wait *was* bounded, and no
> duplicate literal `TERMINAL:` key existed). Found only by killing the
> hung process and bisecting convergence agent-by-agent in isolation. Fix:
> add the `defined $SELF->BOARD->{<flag>}` short-circuit to all 19
> `EXCEPTION` blocks. Confirmed fix: full pipeline `SOLVED` in 0.28s
> post-fix, vs. 13+ min hang before. This check exists so the next sandbox
> catches this exact bug class mechanically, at `chorus-check` generation
> time, instead of requiring a hung process and manual agent-by-agent
> isolation to diagnose.
