** Chosen Strategy
   Choose ONE of the three strategies (or combine them if justified):

   - *Strategy A — discriminating slot (value)*:
     a slot shared by multiple Frames, filtered by value in CHERCHER.
     ~CHERCHER.filtre: '$_->{phase} eq "fiscale"'~
     → fmatch returns too many Frames, the grep reduces them afterwards.
     Effective when values are well distributed AND the overall Frame volume is small.

   - *Strategy B — presence slot (existence)*:
     a slot specific to this agent, set only on the Frames it must process.
     ~CHERCHER.attribut: besoin_agent_xxx~ (no filter)
     → fmatch returns directly and only the relevant Frames.
     Preferred whenever the overall Frame volume is large (avoids combinatorial explosion).

   - *Strategy C — prototype selection (fselect / _ALTERNATIVES)*:
     use ~fselect(slot => value, ...)~ to find the best-matching prototype Frame
     from a declared network (~_ALTERNATIVES~ arrayref on the seed Frame).
     ~my $proto = fselect(type => 'masonry', _alternatives => $BaseMaterial);~
     → returns the highest-scoring candidate; use ~_all => 1~ for a ranked list.
     Preferred when the domain has multiple competing prototypes and the best fit
     must be determined at runtime from observed slot values.

   Chosen strategy : <A | B | C | A+B | …>

** Agent Options (Expert-level)
   Optional flags set directly on the agent frame after construction.

   - ~_LOCK_UNTIL_STABLE~ → ~'Y'~ : Expert skips this agent in the current outer-loop pass
     if any *earlier* agent fired at least one rule in its last ~loop()~ call (~_SUCCES = 1~).
     The agent is NOT permanently locked — it runs in the next outer-loop pass once all
     earlier agents have fully converged (~_SUCCES = 0~ = last ~applyrules()~ pass fired nothing).
     Typical use: a "global conformity check" that runs only after all upstream agents have
     fully stabilised.
     ⚠ ~_SUCCES~ is reset at the *start* of every ~loop()~ call and reflects the LAST
       ~applyrules()~ pass only — "any earlier agent succeeded" ≠ "all have ever fired";
       it means "at least one earlier agent's last pass was still active in this iteration".
     #+BEGIN_SRC perl
     $agent->{_LOCK_UNTIL_STABLE} = 'Y';
     #+END_SRC

   - ~pause()~ / ~wakeup()~ : suspend/resume this agent's ~loop()~ from another agent's
     rule — useful for conditional activation based on pipeline state.
     #+BEGIN_SRC perl
     $other_agent->pause();    # loop() becomes a no-op
     $other_agent->wakeup();   # re-enable
     #+END_SRC

* Ontology
  Domain concepts and their relationships — used to decide which Frames to create and how to name them.

  - Concept A  → Frame ~NameFrameA~ with slots [x, y, z]
  - Concept B  → derives from A (_ISA => $NameFrameA)
  - Relation A↔B → cross-slot on A ~→ b_ref~ or _AFTER hook on slot ~x~

  Patterns for inter-Frame relations — choose the most fitting:

  - *Simple prototype (~_ISA~)*:
    ~ChildFrame → _ISA => $ParentFrame~
    Inherits defaults, normative thresholds and ~_NEEDED~ computations from the parent.
    Use when a concept is a strict specialisation of another.

  - *Frame network (~_ALTERNATIVES~ + ~fselect~)*:
    Declare siblings on the seed Frame: ~_ALTERNATIVES => [$ProtoB, $ProtoC]~
    Select at runtime: ~fselect(prop => val, _alternatives => $ProtoA)~
    Use when the domain has multiple competing prototypes resolved by observed data at runtime.

  - *Forward propagation (~_AFTER~)*:
    Slot ~X~ on ~FrameA~ → ~_AFTER~ updates slot ~Y~ (same or other Frame).
    ~_AFTER => { X => sub { my $ctx = $SELF; $other->set('Y', $ctx->get('X') * factor) } }~
    Use for derived computations that must cascade on every write.

  - *Cross-Frame reference (reference slot)*:
    Slot ~b_ref~ on ~FrameA~ → points to a ~FrameB~ instance (set by Feed.pm or earlier agent).
    Navigate with ~$a->{b_ref}->get('slot')~ or via ~_AFTER~ on the referencing slot.
    Use to model relationships between independent Frame types.

   Control-flow primitives available in EFFET (use sparingly — prefer convergence):
   - ~$agent->cut()~        → exit combination loop for this rule, move to next rule
   - ~$agent->last()~       → exit rule loop for this agent, move to next agent

   - ~$agent->replay_all()~ → restart the whole Expert pipeline from agent 1

     On large pipelines (5+ agents, 200+ Frames), a frequently-firing rule calling
     ~replay_all()~ can turn a 2-second run into a timeout.
     Prefer ~replay()~ (restarts current agent only) whenever possible.

* Constraints & Pitfalls
  Constraints specific to this agent's domain (in addition to generic engine pitfalls):

  - [ ] <norm constraint: e.g. "if field is empty → default = 0, not undef — otherwise fmatch misses the Frame">
  - [ ] <critical order: R01 MUST fire before R03 because it sets the slot R03 consumes>
  - [ ] <edge case: Frame with multiple _ISA → use get() in mode Z if inheritance is ambiguous>
  - [ ] Always end EFFET with ~1~ or a truthy expression
  - [ ] Always add EXCEPTION idempotence on the slot being set
  - [ ] *Guard coherence*: the slot tested in ~EXCEPTION: "defined $f->{X}"~ must be a slot
        *written by this same rule* (~$f->set('X', ...)~ in its own ACTION/EFFET).
        A guard on a slot that may be legitimately pre-set in a cross-test project JSON
        causes silent bypass: the rule is skipped and its other output slots are never computed.
        → ~Chorus::Engine::loadRules()~ emits a ~warn~ automatically at every pipeline run
        for any such mismatch — immediate feedback, not deferred to a ~chorus-check~ regeneration.
  - [ ] The targeting slot must be set BEFORE this agent's register() call
  - [ ] ~_MAX_CYCLES~ (default 10 000) — calibrate when the Frame volume × rule count is high:
        ~$agent->set('_MAX_CYCLES', N)~  (set before ~loop()~ / ~process()~)
  - [ ] ~_MAX_ITER~ on Chorus::Expert (default 10 000) — calibrate for multi-agent pipelines:
        ~$xprt->{_MAX_ITER} = N~ (set after ~new()~, before ~process()~)
  - [ ] ~pause()~ / ~wakeup()~ — if this agent uses these on peer agents, document which agent
        controls activation and under what condition; missing ~wakeup()~ = silent dead pipeline
  - [ ] ~_LOCK_UNTIL_STABLE~ — if set, this agent NEVER runs in a cycle where any earlier agent
        has succeeded; verify that earlier agents eventually stop firing to avoid starvation
  - [ ] ~_ON_DELETE~ demons — if a frame deletes a slot mid-pipeline, ensure the demon does not
        trigger unwanted ~fmatch()~ side effects on other agents still in the same cycle
  - [ ] ~_NEEDED~ is *not cached* — every ~get()~ on a ~_NEEDED~ slot re-evaluates the coderef.
        For expensive computations, cache the result explicitly:
        ~$SELF->set('slot', $computed)~ inside the ~_NEEDED~ sub (converts the slot from
        ~_NEEDED~ to ~_VALUE~ after first evaluation — subsequent ~get()~ calls are O(1)).
  - [ ] ~fselect~ (Strategy C) scores by exact value match — ensure slot values are normalised
        before calling it (lowercase, trim) to avoid missed matches
