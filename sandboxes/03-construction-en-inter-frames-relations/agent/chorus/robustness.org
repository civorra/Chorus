* Domain
  Classification of buildings into Consequence Classes per Section 5 / Requirement A3:

  - Determines the Consequence Class (CC1 / CC2a / CC2b / CC3) from Table 11 (§5.1)
  - CC1: no additional disproportionate collapse measures required
  - CC2a (Lower Risk): effective horizontal ties or floor anchorage required
  - CC2b (Upper Risk): horizontal + vertical ties, or key element design, or notional removal check
  - CC3: systematic risk assessment required
  - Flags buildings where additional robustness measures are needed beyond A1/A2 compliance

  Pipeline position 0/5 (upstream optional) — no dependency on any other agent.
  Does not set targeting slots for downstream agents (standalone verdict).

* Ontology
  Core concepts from corpus §5, Table 11:

  - *Consequence Class 1* → Houses ≤ 4 storeys, agricultural, rarely-occupied buildings
  - *Consequence Class 2a* → 5-storey houses, hotels/flats/offices ≤ 4 storeys, industrial ≤ 3,
    retail ≤ 3 and < 2000m²/storey, single-storey educational, public ≤ 2 and ≤ 2000m²/storey
  - *Consequence Class 2b* → Hotels/flats/offices 5–15 storeys, educational 2–15, retail 4–15,
    hospitals ≤ 3, public 2000–5000m²/storey, car parks ≤ 6 storeys
  - *Consequence Class 3* → All CC2a/2b beyond limits, grandstands > 5000, hazardous processes

* Rule Catalogue
** Rule: R01-consequence-class
   Intent    : Classify building into Consequence Class CC1/CC2a/CC2b/CC3 per Table 11 (§5.1).
               Sets consequence_class, robustness_ok (YES only for CC1), and robustness_note.
   Priority  : 1

   FIND      :
   - ~b~ → attribut: ~type_element~
           [filtre: ~'defined $_->{building_use}'~]

   EXCEPTION : ~defined $b->{consequence_class}~
   EFFECT    :
   #+BEGIN_SRC perl
   use ADA::Agent::Robustness::Helpers qw(consequence_class_table11);

   my $use     = $b->{building_use}          // 'house';
   my $storeys = $b->{num_storeys_building}  // 1;
   my $area    = $b->{floor_area_m2_storey}  // 0;

   my ($cc, $note) = consequence_class_table11($use, $storeys, $area);

   $b->set('consequence_class', $cc);
   $b->set('robustness_ok',     ($cc eq 'CC1') ? 'YES' : 'NO');
   $b->set('robustness_note',   $note);
   1
   #+END_SRC

   Notes: For mixed-use buildings → use the most onerous consequence class (Table 11 Note 1).
          Basements may be excluded from storey count if they meet CC2b robustness (Table 11 Note 2).
          CC3 buildings require a full systematic risk assessment — flag for specialist.

* Perl Helpers
** consequence_class_table11
   Signature   : ~sub consequence_class_table11($use, $storeys, $floor_area_m2) → ($cc, $note)~
   Description : Returns consequence class string and description per Table 11.
                 Inputs: building use category, number of storeys, max floor area per storey.
                 Returns ('CC1'|'CC2a'|'CC2b'|'CC3', description_string).
   Called by   : R01-consequence-class
   Exported    : yes — add to @EXPORT_OK

   #+BEGIN_SRC perl
   # Table 11 — Building consequence classes
   # Source corpus: Table 11 (p.44)
   #
   # Classification logic:
   # house:
   #   storeys ≤ 4  → CC1
   #   storeys == 5 → CC2a
   #   storeys > 5  → (no specific entry, treat as CC2b if not exceeding 15)
   # hotel, flat, apartment, residential (non-house):
   #   storeys ≤ 4  → CC2a
   #   4 < storeys ≤ 15 → CC2b
   #   storeys > 15 → CC3
   # office:
   #   storeys ≤ 4  → CC2a
   #   4 < storeys ≤ 15 → CC2b
   #   storeys > 15 → CC3
   # industrial:
   #   storeys ≤ 3  → CC2a
   #   storeys > 3  → CC3 (exceeds limit)
   # retail:
   #   storeys ≤ 3 AND floor_area < 2000m² → CC2a
   #   3 < storeys ≤ 15 → CC2b
   #   storeys ≤ 15 AND floor_area ≥ 2000 AND floor_area < 5000 → CC2b
   #   storeys > 15 OR floor_area ≥ 5000 → CC3
   # school / educational:
   #   storeys == 1 → CC2a
   #   1 < storeys ≤ 15 → CC2b
   #   storeys > 15 → CC3
   # hospital:
   #   storeys ≤ 3  → CC2b
   #   storeys > 3  → CC3
   # public (members of public admitted):
   #   storeys ≤ 2 AND floor_area ≤ 2000 → CC2a
   #   floor_area 2000–5000 → CC2b
   #   storeys > 2 AND floor_area > 5000 → CC3
   # agricultural → CC1
   # car_park:
   #   storeys ≤ 6  → CC2b
   #   storeys > 6  → CC3
   # hazardous → CC3
   # rarely_occupied → CC1 (provided distance condition met — feed must pre-verify)
   #+END_SRC

* Constraints & Pitfalls
  - [ ] Mixed-use buildings: use the most onerous consequence class (Table 11 Note 1) —
        feed should pre-determine the dominant use or submit multiple Frames
  - [ ] Basement storeys may be excluded from the storey count if they meet CC2b robustness
        requirements (Table 11 Note 2) — feed must apply this exclusion before submission
  - [ ] CC3 buildings require a full systematic risk assessment by a structural engineer —
        this agent flags the requirement but cannot prescribe the assessment content
  - [ ] 'rarely_occupied' buildings (CC1) must additionally satisfy the distance condition:
        no part of the building closer than 1.5 × height to another building or occupied area
        — feed must pre-verify; this agent cannot check site distances
  - [ ] Agricultural buildings: CC1 regardless of storeys (Table 11 rows)
  - [ ] Grandstands > 5000 spectators: always CC3 — feed should set building_use = 'grandstand'
        (not in current Aliases — add in next enrichment pass)
  - [ ] _MAX_CYCLES recommended: 3 building Frames × 1 rule × 5 agents × 10 = 150
  - [ ] ⚠️ _CYCLE and _SUCCES are reset to 0 at the start of every loop() call — do not use
        them as cumulative counters across loop() calls. To accumulate a global total,
        write to a dedicated BOARD slot from within a rule.
        [ref: pitfalls.org §_CYCLE and _SUCCES — DISCOVERED 2026-07-24]
