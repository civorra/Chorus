* Règles directement encodables

** RGS v2.0 Annexe B1 — Algorithmes et clés

Contraintes françaises sur les algorithmes (souvent plus strictes que CABF) :

- RSA : 2048 bits minimum (3072 recommandé post-2025)
- ECDSA : P-256 minimum (P-384 recommandé)
- SHA-256 minimum pour empreintes
- AES-128 minimum pour chiffrement symétrique
- Triple-DES : déprécié

→ Règles YAML : comparer =key_size=, =signature_algorithm= aux seuils RGS

** RGS — Durées de validité

| Type de certificat            | Durée maximale |
|-------------------------------+----------------|
| Certificat personne physique  | 3 ans          |
| Certificat serveur            | 2 ans          |
| Certificat AC racine          | 20 ans         |
| Certificat AC intermédiaire   | 10 ans         |

→ Règle YAML : =validity_days= selon =subject_type= et =is_ca=

** RGS — Extensions obligatoires

Pour les certificats utilisés dans le cadre du RGS :
- =keyUsage= : critique, valeurs selon profil
- =certificatePolicies= : OID RGS requis
- =cRLDistributionPoints= : obligatoire
- =authorityInformationAccess= (OCSP) : obligatoire

* Note sur la qualification ANSSI

Les prestataires de confiance qualifiés ANSSI doivent respecter le RGS **et** les normes
ETSI (EN 319 401, EN 319 411-1 ou -2 selon le niveau).
La qualification ANSSI NivEtoile1 / NivEtoile2 / NivEtoile3 correspond aux niveaux
LCP / NCP / NCP+ d'ETSI.
