* Domain
  This agent validates requirements specific to certificates issued to natural persons,
  as defined in ETSI EN 319 412-2:
  - Subject field mandatory attributes (§4.2.4 — NAT-4.2.4-*)
  - Key usage settings (§4.3.2 — NAT-4.3.2-*)
  - Revocation information presence: CRL distribution points and/or OCSP (§4.3.11, §4.4.1)
  - EU Qualified Certificate policy identifiers (§5.1, §5.2)

  It runs after CertProfileCommon (pos. 1) which validates common data structures.
  It targets NAT frames that have been cleared by agent 1 (needs_nat_validation slot
  set by CertProfileCommon R04 on conformant nat frames).

* Targeting Slots                                                        :SCOPE:

** Chosen Strategy
   - *Strategy B — presence slot (existence)*:
     CertProfileCommon (R04) sets ~needs_nat_validation~ on every NAT SubjectIdentifier
     frame after computing cert_profile_result. This agent scopes on that slot.

   Chosen strategy : B
   Justification   : Volume is bounded, frame type is homogeneous (NAT only).
                     Strategy B is safe and efficient; avoids Cartesian products.

* Rule Catalogue

** Rule: R09-nat-subject-mandatory-attrs
   Intent    : Validate that the subject field of a NAT certificate contains all mandatory
               attributes per §4.2.4: countryName + (givenName and/or surname OR pseudonym)
               + commonName. Pseudonym must NOT be combined with givenName/surname.
   FIND      : ~f~ → attribut: ~needs_nat_validation~
   EXCEPTION : defined $f->{nat_subject_ok}
   EFFECT    :
   #+BEGIN_SRC perl
   my $cn      = $f->get('has_common_name')  // '';
   my $country = $f->get('has_country_name') // '';
   my $gn      = $f->get('has_given_name')   // '';
   my $sn      = $f->get('has_surname')      // '';
   my $pseudo  = $f->get('has_pseudonym')    // '';

   # NAT-4.2.4-1: countryName + (givenName/surname OR pseudonym) + commonName mandatory
   my $ok = 'OUI';
   $ok = 'NON' unless ($country eq 'Y');                         # countryName mandatory
   $ok = 'NON' unless ($cn eq 'Y');                              # commonName mandatory
   $ok = 'NON' unless (($gn eq 'Y' || $sn eq 'Y') || $pseudo eq 'Y');  # name identity mandatory
   # NAT-4.2.4-4: pseudonym shall not be present if givenName/surname are present
   $ok = 'NON' if ($pseudo eq 'Y' && ($gn eq 'Y' || $sn eq 'Y'));

   $f->set('nat_subject_ok', $ok);
   1
   #+END_SRC

** Rule: R10-nat-key-usage
   Intent    : Validate keyUsage extension for NAT certificates per §4.3.2 Table 1.
               Exactly one valid combination (A–F) must be present.
               If commitment_cert = 'Y', only type A, B or F is allowed (NAT-4.3.2-2).
   FIND      : ~f~ → attribut: ~needs_nat_validation~
   EXCEPTION : defined $f->{nat_key_usage_ok}
   EFFECT    :
   #+BEGIN_SRC perl
   my $bits = $f->get('key_usage_bits') // '';

   # Valid keyUsage combinations — Table 1 ETSI EN 319 412-2 §4.3.2
   my %valid_combos = (
     'nonRepudiation'                                    => 'A',  # bit 1 only
     'nonRepudiation,digitalSignature'                   => 'B',  # bits 1+0
     'digitalSignature'                                  => 'C',  # bit 0 only
     'digitalSignature,keyEncipherment'                  => 'D',  # bits 0+2
     'digitalSignature,keyAgreement'                     => 'D',  # bits 0+4
     'keyEncipherment'                                   => 'E',  # bit 2 only
     'keyAgreement'                                      => 'E',  # bit 4 only
     'nonRepudiation,digitalSignature,keyEncipherment'   => 'F',  # bits 1+0+2
     'nonRepudiation,digitalSignature,keyAgreement'      => 'F',  # bits 1+0+4
   );

   # Normalize: sort comma-sep bits alphabetically for reliable key lookup
   my $key = join(',', sort split(/,\s*/, $bits));
   my $combo = $valid_combos{$key};

   my $ok = defined($combo) ? 'OUI' : 'NON';

   # NAT-4.3.2-2: commitment cert must be type A, B or F
   if ($ok eq 'OUI' && ($f->get('commitment_cert') // '') eq 'Y') {
     $ok = 'NON' unless ($combo =~ /^[ABF]$/);
   }

   $f->set('nat_key_usage_ok', $ok);
   1
   #+END_SRC

** Rule: R11-revocation-info
   Intent    : Validate revocation information presence per §4.3.11 and §4.4.1.
               CRL or OCSP must be present UNLESS validity_assured + no_rev_avail are both set.
   FIND      : ~f~ → attribut: ~needs_nat_validation~
   EXCEPTION : defined $f->{revocation_ok}
   EFFECT    :
   #+BEGIN_SRC perl
   my $crl      = $f->get('has_crl_dp')          // '';
   my $ocsp     = $f->get('has_ocsp')             // '';
   my $va       = $f->get('has_validity_assured') // '';
   my $no_rev   = $f->get('has_no_rev_avail')     // '';

   # GEN-4.3.11-2 / GEN-4.4.1-8: CRL or OCSP required
   # GEN-4.3.11-2A / GEN-4.4.1-8A: exception when validity_assured AND no_rev_avail present
   my $ok;
   if ($crl eq 'Y' || $ocsp eq 'Y') {
     $ok = 'OUI';  # CRL or OCSP present — always conformant
   } elsif ($va eq 'Y' && $no_rev eq 'Y') {
     $ok = 'OUI';  # validity assured + NoRevAvail — RFC 9608 exception satisfied
   } else {
     $ok = 'NON';  # neither CRL/OCSP nor valid exception
   }

   $f->set('revocation_ok', $ok);
   1
   #+END_SRC

** Rule: R15-qcstatements
   Intent    : For EU Qualified Certificates, QCStatements SHALL be present (§5.1 QCS-5.1-1).
               Silently skips non-qualified frames (is_qualified absent or ≠ 'Y').
   FIND      : ~f~ → attribut: ~needs_nat_validation~
   EXCEPTION : defined $f->{qcstatements_ok}
   EFFECT    :
   #+BEGIN_SRC perl
   unless (($f->get('is_qualified') // '') eq 'Y') { return 0; }
   my $qcs = $f->get('has_qcstatements') // '';
   $f->set('qcstatements_ok', ($qcs eq 'Y') ? 'OUI' : 'NON');
   1
   #+END_SRC

** Rule: R12-nat-compute-result
   Intent    : Aggregate nat_subject_ok + nat_key_usage_ok + revocation_ok into nat_profile_result.
               Must run after R09, R10, R11 (alphabetical load order guarantees this).
   FIND      : ~f~ → attribut: ~needs_nat_validation~
   EXCEPTION : defined $f->{nat_profile_result}
   EFFECT    :
   #+BEGIN_SRC perl
   my $subj_ok = $f->get('nat_subject_ok');
   my $ku_ok   = $f->get('nat_key_usage_ok');
   my $rev_ok  = $f->get('revocation_ok');

   # KO if any checked field is NON
   my $result = 'OK';
   $result = 'KO' if (defined $subj_ok && $subj_ok eq 'NON');
   $result = 'KO' if (defined $ku_ok   && $ku_ok   eq 'NON');
   $result = 'KO' if (defined $rev_ok  && $rev_ok  eq 'NON');

   $f->set('nat_profile_result', $result);
   1
   #+END_SRC

* Constraints & Pitfalls
  - [ ] ~needs_nat_validation~ must be set by CertProfileCommon R04 on NAT frames BEFORE
        this agent becomes active. Verify R04 ACTION sets this slot (update required).
  - [ ] R10 normalizes ~key_usage_bits~ by sorting — project JSON must use consistent bit names
        (see Aliases table). A mismatch silently produces ~combo = undef~ → NON verdict.
  - [ ] R11: if ~has_validity_assured~ is set but ~has_no_rev_avail~ is absent → NON.
        Conservative: a validity-assured cert without NoRevAvail AND without CRL/OCSP is
        non-conformant per GEN-4.3.11-2A.
  - [ ] R12 runs only after R09/R10/R11 have fired on the same frame. If any of those rules
        failed to set their slot (e.g. CONDITION miss), R12 sees undef for that slot and
        treats it as untested — does NOT force KO. Intentional: checks only what is present.
  - [ ] EU Qualified Certificate QCS check (§5.1 QCS-5.1-1: has_qcstatements mandatory when
        is_qualified = Y) is deferred to next --enrich cycle.
  - [ ] _MAX_CYCLES: with 2 agents × ~13 rules × N frames, calibrate:
        ~$agent->set('_MAX_CYCLES', N * 13 * 2)~
