* Domain
  Aggregates all per-domain verdicts into a final compliance_status per element
  (§6.1). Terminates the pipeline when all elements carrying =needs_compliance=
  have received their status (§6.2).

* Targeting slots
** Strategy
   Strategy B — presence slot =needs_compliance=.
   Set by initial Feed on all elements. This is the entry-point slot — it
   persists through the entire pipeline so this final agent can always locate
   all elements regardless of intermediate processing.

** Table
   | Slot             | Set by       | Consumed by                        |
   |------------------+--------------+------------------------------------|
   | needs_compliance | initial feed | This agent (TimberFrame::Agent::Compliance) |

** Pre-population contract
   Feed.pm sets =needs_compliance= on all elements at load time.

* Pipeline I/O
** Incoming slots
   - =type_element= — element type
   - =needs_compliance= — targeting slot
   - =qualified= — from qualification agent (YES/NO)
   - =frame_ok= — from geometry agent (YES/NO) — optional (not set on non-structural elements)
   - =thermal_ok= — from thermal agent (YES/NO) — optional (set only on insulation/VCL)
   - =fire_ok= — from fire agent (YES/NO)
   - =collective= — project-level occupancy flag (0 or 1)

** Outgoing slots
   - =compliance_status= — 'COMPLIANT' or 'NON-COMPLIANT'
   - =compliance_summary= — comma-separated list of failed checks (if any)

* Constraints & Pitfalls
  - R01 must wait for all upstream agents to have written their verdict slots.
    CONDITION guards ensure slots are present before computing compliance.
  - For structural elements: frame_ok must be present; thermal_ok may be absent (not applicable).
  - For insulation/VCL: frame_ok absent is normal; rule must not treat absence as failure.
  - R02 termination rule uses two-rule pattern: R01 per-element, R02 EXCEPTION fmatch.
  - _MAX_CYCLES recommended: engine default 10 000 sufficient for demo.
